# modules/radiology — тренажёр чтения снимков

Модуль обучения врачей и резидентов **правильному чтению исследований** —
КТ, МРТ, УЗИ, рентген и т.д. Учащийся не выбирает A/B/C, а работает как
рентгенолог: смотрит снимок, идёт по протоколу осмотра, **локализует
находки прямо на изображении**, ставит диагноз — и получает оценку с
разбором. Смонтирован в `index.js` как `/api/v1/radiology`.

Это MVP-этап 0: одна модальность (рентген ОГК), готовые анонимные
PNG/JPEG (не DICOM), гибридный скоринг. Дальше — вторые модальности и,
опционально, настоящий DICOM-вьюер.

## Почему модуль глобальный, а не подмодуль education/clinic

Как и `education`, аудитория — врачи и резиденты вне зависимости от
клиники, поэтому **нет `tenantMiddleware`** и `tenantScoped`. Своя лестница
ролей (`middlewares/radiologyAuth.js`), потому что `common/auth/can.js`
завязан на `ClinicMembership`, которого у учащегося может не быть.

Отдельно от `education`, а не подмодулем: домен принципиально другой —
не текстовый вопрос, а изображение + разметка + пространственный скоринг.
Смешивать это с `ExamItem` значило бы раздувать банк вопросов чуждой
логикой.

Лестница ролей — та же, что в education:

| | Кто | Что может |
| --- | --- | --- |
| `requireLearner` | любой авторизованный | проходить кейсы |
| `requireAuthor` | `admin` | создавать кейсы, размечать эталон |
| `requireReviewer` | `admin` | публиковать, принимать/отклонять ревью |

## «Одна система на одно исследование» — `reading-systems/`

Ключевое проектное решение. КТ читают не так, как УЗИ: разные инструменты,
протокол осмотра, шаблон заключения, веса оценки. Поэтому:

**Общее ядро (модели, попытки, скоринг) + плагин на каждую модальность.**

`reading-systems/` — реестр плагинов по образцу `education-ingest/extractors/`:
доступ по ключу-модальности, добавить модальность = добавить файл-плагин и
строку в `index.js`, не трогая ядро. Плагин (`defineReadingSystem`) задаёт:

- `viewer` — что умеет просмотрщик (окна, листание срезов, инструменты);
- `checklist` — протокол систематического осмотра (это и учит «читать по
  порядку, ничего не пропуская»);
- `scoring` — веса компонентов, порог, радиус совпадения находок.

Словарь находок (палитра ярлыков) не дублируется в плагине — выводится из
`lexicon/lexicon.js` по модальности кейса.

## Модель данных

- **RadiologyCase** (`radiology_cases`) — кейс = одно исследование + ВСТРОЕННЫЙ
  эталон эксперта:
  - `images[]` — анонимные срезы (R2-URL), `pixelSpacingMm` для замеров;
  - `findings[]` — эталонные находки: `label` (из словаря), `significance`
    (critical/major/incidental), `geometry` (point/rect/ellipse/polygon,
    координаты **нормализованы к 0..1**), `explanation`;
  - `impression` — эталонное заключение + принятые ключи диагноза;
  - `source` — юр. метка происхождения (как в education);
  - `deidentified` — без `true` публикация запрещена (HIPAA).
- **RadiologyAttempt** (`radiology_attempts`) — попытка: ответ учащегося
  (его разметка + чек-лист + заключение), покомпонентная оценка, разбор.
- **RadiologyEvent** (`radiology_events`) — доменный аудит (своя коллекция,
  как у anthropometry). В `metadata` — только структурное, без PHI.

Эталон учащемуся **не отдаётся до сдачи**: `sanitizeForLearner` вырезает
`findings` и `impression`, оставляя снимок, клинику и конфиг системы чтения.

## Скоринг — гибрид

`radiology-attempts/services/scoring.service.js` — детерминированное ядро
(без ИИ, «ключ ответа»):

- **detection** — нашёл ли находки там, где они есть. Разметка учащегося
  сопоставляется с эталоном по расстоянию центров (не пиксель-в-пиксель):
  учим «увидел в нужной зоне». Взвешено по значимости; пропуск critical
  штрафуется сильнее, ложная тревога — минусует;
- **classification** — верно ли назвал найденное;
- **checklist** — доля пройденных пунктов протокола;
- **diagnosis** — попал ли в принятый набор ключей.

`impressionGrader.js` — вторая половина гибрида: оценка **свободного текста**
заключения. Реестр бэкендов через env (по образцу экстракторов):

```bash
RADIOLOGY_IMPRESSION_GRADER=heuristic   # по умолчанию: работает без ключей
RADIOLOGY_IMPRESSION_GRADER=claude      # точнее, платно (точка расширения)
```

Итог (`combineTotal`) — взвешенная сумма; компоненты со `score === null`
(выключенный ИИ, кейс без диагноза) **исключаются из нормировки**, а не
занижают балл.

## API

Всё под `/api/v1/radiology`, закрыто `requireLearner`.

| Метод | Путь | Роль | Что делает |
| --- | --- | --- | --- |
| GET | `/reading-systems` | learner | Конфиг систем чтения (вьюер, чек-лист) |
| GET | `/cases` | learner | Список кейсов (learner — только published; `?scope=all` для admin) |
| POST | `/cases` | author | Создать кейс (draft) |
| GET | `/cases/:id` | learner/author | Полный (admin) или санитизованный (learner) кейс |
| PATCH | `/cases/:id` | author | Правка draft/rejected |
| POST | `/cases/:id/submit` | author | На ревью |
| POST | `/cases/:id/review` | reviewer | approve (гейт публикации) / reject |
| DELETE | `/cases/:id` | reviewer | Архивировать |
| POST | `/cases/:id/attempts` | learner | Начать попытку → санитизованный кейс |
| GET | `/attempts` | learner | История |
| GET | `/attempts/:id` | learner | Попытка (+ разбор, если сдана) |
| POST | `/attempts/:id/submit` | learner | Сдать ответ → оценка + разбор |

## Что переиспользуется из проекта

- скелет попыток/ревью/статусов — идеи из `education`;
- enum модальностей и загрузка в R2 — из `clinic` (ImagingFormModal);
- фронтовый canvas-движок (zoom/pan/оверлеи/координаты) — из `simulation`
  (для вьюера и разметки; фронтенд — следующий этап);
- своя коллекция аудита — по образцу `anthropometry`.

## Что НЕ сделано на этом этапе (осознанно)

- **Фронтенд** (вьюер учащегося + инструмент авторинга на canvas) — следующий
  этап; бэкенд-контракт под него готов (`GET /reading-systems` отдаёт конфиг).
- **DICOM** — работаем с готовыми PNG/JPEG; настоящий вьюер (cornerstone)
  и DICOM-анонимизация отложены.
- **claude-грейдинг** свободного заключения — заглушка с откатом на
  эвристику; точка расширения помечена в `impressionGrader.js`.
- **Тесты** `__tests__/radiology/` — под скоринг (детекция/классификация/
  нормировка) и гейт публикации; движок уже проверен ручным прогоном.
