# Справочник медицинских кодов

Болезни (МКБ-10) и, дальше по плану, вмешательства (ICHI). Смонтирован в
`/api/v1/medical-codes`.

## Зачем модуль, если автокомплит МКБ уже был

Был — `client/src/components/ICD10Autocomplete.jsx` ходил из браузера врача в
публичный API NLM (США). Три следствия, из-за которых понадобился свой
справочник:

- **поиск только по-английски** — NLM отдаёт ICD-10-CM без переводов, и врач,
  работающий на русском, вынужден переводить диагноз в уме;
- **внешняя зависимость в рабочем пути** — нет связи, лёг NLM, заблокировали
  домен: подставить код нельзя;
- **некуда положить переводы** — а их нужно пять.

Плюс `codeTitle` в записях надиктовки остаётся пустым по построению: модуль
надиктовки сознательно не подставляет туда речь врача, а взять официальное
название было неоткуда.

## Устройство

```
medicalCodes/
  index.js                     агрегатор + точка авторизации
  models/medicalCode.model.js  коллекция medical_codes
  services/codeSearch.service.js  поиск (две стратегии)
  routes/codes.routes.js       HTTP
  middlewares/codesAuth.js     доступ медперсоналу
  scripts/importIcd10cm.js     загрузка справочника
```

Модуль **глобальный**: без `tenantMiddleware`, без `clinicId` в модели. Коды
МКБ одинаковы для всех клиник и не содержат данных пациентов — это
единственная медицинская коллекция проекта без тенанта, и так задумано.
Авторизация своя (`codesAuth.js`), потому что `common/auth/can.js` завязан на
`ClinicMembership`; сделано по образцу `radiology` и `diagnostics`.

## Две стратегии поиска

| Стратегия | Когда | Что умеет |
| --- | --- | --- |
| `atlas` | есть индекс Atlas Search | опечатки, частичные слова, ранжирование по языку |
| `regex` | всё остальное | точный поиск по коду и подстроке в названии |

Стратегия выбирается **один раз** при первом запросе: пробуем `$search`, при
ошибке запоминаем, что индекса нет, и дальше идём коротким путём. Проверять на
каждый ввод буквы было бы дорого.

Ответ поиска содержит поле `strategy` — по нему видно, какой путь сработал.

### Как включить Atlas Search

```bash
node modules/medicalCodes/scripts/createSearchIndex.js          # создать/обновить
MONGODB_DB=DOCPATS_NEW node modules/medicalCodes/scripts/createSearchIndex.js --wait
```

Скрипт идемпотентен: существующий индекс он обновляет, а не заводит второй.
Сборка идёт в фоне на стороне Atlas — до статуса `READY` поиск продолжает
работать обычным Mongo, и это не ошибка.

Раньше здесь было написано, что индекс заводится только руками в интерфейсе.
Это устарело: начиная с MongoDB 7.0 драйвер умеет `createSearchIndexes`, и на
Atlas команда доступна обычному подключению. Интерфейс остаётся запасным
путём — Atlas → Search → Create Search Index, имя **`medical_codes_search`**,
коллекция `medical_codes`, та же конфигурация:

```json
{
  "mappings": {
    "dynamic": false,
    "fields": {
      "codeNormalized": [
        { "type": "string" },
        { "type": "autocomplete", "minGrams": 2, "maxGrams": 8 }
      ],
      "titles": {
        "type": "document",
        "fields": {
          "en": { "type": "string" },
          "ru": { "type": "string" },
          "az": { "type": "string" },
          "tr": { "type": "string" },
          "ar": { "type": "string" }
        }
      },
      "system": { "type": "string" }
    }
  }
}
```

После создания перезапустите процесс (или дождитесь рестарта) — запомненная
стратегия сбросится, и поиск переключится на Atlas.

**Без индекса модуль работает.** Хуже — без терпимости к опечаткам, — но
работает, и это осознанный выбор: тесты идут против `mongodb-memory-server`,
где Atlas Search недоступен в принципе.

## Загрузка справочника

```bash
# проверить, ничего не записывая
node modules/medicalCodes/scripts/importIcd10cm.js --dry-run --limit 1500

# полная загрузка (~75 000 кодов, несколько минут)
node modules/medicalCodes/scripts/importIcd10cm.js
```

Скрипт **идемпотентен**: повторный запуск обновит записи, а не удвоит их.
Прервали на середине — просто запустите снова.

## Переводы названий

```bash
# что уже переведено
node modules/medicalCodes/scripts/translateCodes.js --status

# пробный перевод пяти названий — реальный вызов модели, база не меняется
node modules/medicalCodes/scripts/translateCodes.js --lang ru --dry-run

# перевести партию
node modules/medicalCodes/scripts/translateCodes.js --lang ru --max 3000

# партия с другим потолком трат (по умолчанию $60 за запуск)
node modules/medicalCodes/scripts/translateCodes.js --lang ru --max 80000 --budget 100
```

Официальных переводов для МКБ-10-**CM** не существует: ВОЗ переводит свою
версию (~14 000 рубрик), а здесь американская модификация на 74 719 кодов.
Поэтому переводим моделью, партиями по 50 названий за запрос.

**Перевод стоит денег**, поэтому запускает его человек, а не сервер при старте.
Без `--yes` скрипт показывает оценку и ждёт подтверждения. Прерывать можно:
следующий запуск продолжит с того места, где остановился.

Замеры на боевой базе (Opus 5, пачки по 50): **$0.87 за 1000 названий** для
русского, $1.19 турецкий, $1.21 арабский, $1.51 азербайджанский — у последних
модель тратит заметно больше выходных токенов на то же название. Скорость —
около 2.7 названия в секунду, то есть полный язык это ~7 часов и ~$70.
Модель меняется через `MEDICAL_CODES_TRANSLATION_MODEL`.

### Потолок трат — почему он обязателен

**Ключ Anthropic в проекте один на всё.** Этим же балансом живут надиктовка,
диагностика, ИИ-консультация, ночная генерация кейсов радиологии и движок
новостей на втором сервере. Массовый перевод идёт часами без присмотра, поэтому
способен доесть баланс ночью — и обнаружится это утром отказом у врача, а не в
выводе скрипта. Отдельный API-ключ не спасает: баланс общий на организацию.

Поэтому у запуска есть предел трат, по умолчанию **$60** за прогон
(`--budget`, либо `MEDICAL_CODES_TRANSLATION_BUDGET`). Проверяется перед каждой
пачкой по фактически израсходованным токенам, а не по прикидке. `--budget 0`
снимает ограничение — осознанно, для случая, когда за балансом следят.

Три вещи, которые тут важны и закрыты кодом:

- **Сдвиг переводов.** Если модель вернёт на один перевод меньше, названия
  разъедутся по кодам молча — гастрит получит имя синусита. Пачка с
  несовпадающей длиной отбрасывается целиком.
- **Отказ модели.** На медицинском материале (травмы, отравления) классификатор
  иногда отвечает отказом — это HTTP 200 со `stop_reason: "refusal"`, а не
  ошибка. Такая пачка не записывается.
- **Разовый сбой не обрывает прогон.** Раньше выход был по первой же неудачной
  пачке, и многочасовая работа гибла от одной перегрузки сервиса. Теперь три
  попытки с паузами 5с/20с/60с, затем прогон переступает через пачку и идёт
  дальше; остановка — только когда не даются три пачки подряд (кончились
  деньги, отозван ключ, сервис недоступен).

## Данные и лицензии

| Система | Что | Лицензия |
| --- | --- | --- |
| `icd10cm` | МКБ-10-CM, ~75 000 кодов, только английский | public domain (US) |
| `icd10who` | МКБ-10 ВОЗ, ~14 000, есть официальные переводы | свободно, нужна регистрация в ICD API |
| `ichi` | вмешательства (операции) | свободно, ВОЗ |

**CPT (AMA) использовать нельзя** — платная лицензия. Если понадобятся коды
операций США, это отдельное юридическое решение, а не техническая задача.

Переводов на азербайджанский и турецкий ВОЗ не даёт: их придётся делать самим.

## API

```
GET /api/v1/medical-codes/search?q=тонзиллит&system=icd10cm&limit=20
GET /api/v1/medical-codes/stats
GET /api/v1/medical-codes/:system/:code
GET /api/v1/medical-codes/health          (без авторизации, для мониторинга)
```

Язык берётся из заголовка `X-Language` (общий механизм `common/utils/requestLang.js`),
а не из параметра запроса — врач ищет на языке своего интерфейса.

## Граница, которую нельзя размывать

Подбор кода — **подсказка, а не решение**. Код уходит в статистику и в счета,
поэтому подставлять его автоматически нельзя ни при какой уверенности модели.
Врач выбирает, система предлагает. Та же граница, что в `diagnostics`
(`advisory: true`) и в `dictation` (код только при однозначном соответствии,
иначе `null`).
