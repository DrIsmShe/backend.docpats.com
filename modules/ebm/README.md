# Модуль ebm — доказательная медицина

Врач задаёт клинический вопрос — система показывает, **что по нему есть в
PubMed**, разложенное по силе дизайна исследования.

Первый этап: только поиск и отбор. Модели здесь нет вовсе.

## Главное правило: модель к поиску не допускается

Названия работ, журналы, годы, PMID и DOI приходят из PubMed и только из
PubMed. Это не осторожность вообще, а вывод из замера на собственных данных
проекта: из 80 ссылок, написанных моделью по памяти, **14 указывали на
несуществующие работы, ещё 20 — на чужие**. Для статьи это стыдно; здесь врач
может назначить препарат.

Место модели — позже и отдельно: пересказать **найденное**. Первый этап работает
без неё и проверяется целиком: любую ссылку из ответа можно открыть.

## Ступени доказательности

`services/evidence.service.js`, константа `EVIDENCE_LEVELS`:

| Ранг | Ступень | Фильтр PubMed |
| --- | --- | --- |
| 1 | Мета-анализы | `"meta-analysis"[pt]` |
| 2 | Систематические обзоры | `"systematic review"[pt]` |
| 3 | Клинические рекомендации | `("practice guideline"[pt] OR "guideline"[pt])` |
| 4 | Рандомизированные исследования | `"randomized controlled trial"[pt]` |
| 5 | Наблюдательные исследования | `cohort studies[mh]`, `case-control studies[mh]`, `observational study[pt]` |

Тип публикации в PubMed — **индексированное поле**, его проставляют индексаторы
NLM. Поэтому раскладка машинная и воспроизводимая: она не зависит ни от нас, ни
от модели.

Мнения, редакционные статьи и письма (`comment[pt]`, `editorial[pt]`,
`letter[pt]`) исключаются из выдачи целиком: в иерархии доказательств они стоят
ниже всего, а на странице выглядят так же убедительно, как мета-анализ.

**Это не GRADE.** Настоящая оценка по GRADE учитывает риск систематической
ошибки, согласованность, косвенность и точность — всё это требует чтения полных
текстов человеком. Здесь говорится только о **типе источника**, и называть это
уровнем доказательности было бы подлогом. Формулировка итога (`verdict`)
намеренно описывает **полноту найденного**, а не эффективность лечения; на это
есть отдельный тест.

## Ловушка, ради которой стоит читать этот файл

PubMed **не сообщает, что не понял слово** — он молча его выбрасывает. Русский
запрос теряется целиком, скобка `(запрос)` становится пустой, и выражение
`(пусто) NOT комментарии` означает уже не «ничего», а **«вся база минус
комментарии»**.

Замер на живом PubMed: фраза «хренотень какая-то несуществующая» вернула
**2 447 841 публикацию**, среди них 1962 «мета-анализа». Настоящие работы с
настоящими PMID — просто ни одна не про вопрос врача. Это опаснее пустого
ответа: пустой виден сразу, а этот выглядит как исчерпывающая подборка
доказательств.

Поэтому `searchEvidence` **сначала спрашивает голый запрос**, без единого
фильтра. Пока не подтверждено, что PubMed понял хоть одно слово, фильтры не
приклеиваются. Заодно дешевле: на пустой теме уходит один запрос вместо шести.

Регрессионный тест — `__tests__/ebm/evidenceSearch.test.js`, блок «запрос,
который PubMed не понял».

## Ограничения NCBI

Лимит считается **на IP сервера и общий на весь проект**: перебор одним
пользователем отнимает PubMed у всех остальных, а за упорство NCBI блокирует
адрес — снимается вручную и долго.

- Ограничитель в `services/pubmed.service.js` — очередь на промисах, а не
  отметка времени: наивная версия пропускает параллельные вызовы разом.
- Пауза: 500 мс без ключа (3/с — это «не чаще», и на 350 мс живой прогон уже
  ловил 429), 120 мс с ключом. В тестах — 0.
- При 429 — **ровно один** повтор через 2,5 с.
- HTTP-лимит: 20 поисков в минуту **на пользователя** (не на IP: врачи одной
  клиники сидят за общим NAT).

`PUBMED_API_KEY` бесплатный и поднимает лимит с 3 до 10 запросов в секунду.
Получается в личном кабинете NCBI; при заметной нагрузке нужен.

## Эндпоинты

Все под `/api/v1/ebm`, доступ — медицинскому персоналу (`doctor`, `admin`,
`clinic_admin`, `clinic_staff`). Пациенты не допускаются: прячем не данные —
PubMed открыт всем, — а интерфейс, который читается как «назначь себе лечение
сам».

```
GET /health                     — без авторизации, для мониторинга
GET /levels                     — справочник ступеней
GET /search?q=…&years=…&perLevel=…&levels=…
```

`q` уходит в PubMed как есть: синтаксис PubMed поддерживается целиком
(`AND`/`OR`/`NOT`, `[tiab]`, `[mh]`), и опытный врач может им пользоваться.
`levels` — список ключей через запятую, чтобы запросить одну ступень и не
тратить шесть обращений к NCBI.

Ответ:

```jsonc
{
  "query": "(metformin AND prediabetes) NOT (comment[pt] OR …)",
  "totalAnyDesign": 1130,
  "notUnderstood": [],        // слова, которых PubMed не знает
  "levels": [ { "key": "meta_analysis", "total": 25, "items": [ … ] }, … ],
  "verdict": { "kind": "strong", "text": "…" }
}
```

`verdict.kind`: `strong` | `trials_only` | `weak` | `nothing` |
`not_understood`.
