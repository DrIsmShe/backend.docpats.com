# Перенос данных через админку

Выгрузка и загрузка базы целиком или отдельными коллекциями.
Маршруты: `/api/admin/transfer/*`, страницы в меню админки — «Экспорт БД»,
«Импорт БД», «Экспорт коллекций», «Импорт коллекций».

```
GET  /transfer/databases            какие базы доступны
GET  /transfer/collections?database=…   состав базы: коллекции, счётчики, объём
POST /transfer/export-database      { database, password }          → файл
POST /transfer/export-collection    { database, collection, password } → файл
POST /transfer/import-database      multipart: file + database + password
POST /transfer/import-collection    multipart: file + database + collection + password
```

Две базы, обе на одном кластере Atlas и потому доступны через одно соединение:
`DOCPATS_NEW` (платформа) и `DOCPATS_AI_NEWS` (движок новостей). Список
**закрытый**: без него параметр `database` стал бы способом прочитать служебные
базы кластера (`admin`, `config`, `local`) штатной кнопкой админки.

## Почему выгрузка — POST, а не GET

Она требует подтверждения паролем, а пароль в строке запроса оседает в
журналах nginx, в истории браузера и в заголовке `Referer`. В теле POST-запроса
он туда не попадает. Побочно: выгрузку базы нельзя запустить одной ссылкой,
открытой в чужой вкладке.

## Формат файла

```json
{
  "format": "docpats-dump-v2",
  "database": "DOCPATS_NEW",
  "exportedAt": "2026-08-12T05:00:00.000Z",
  "collections": { "users": [ … ], "medical_codes": [ … ] },
  "stats": { "users": 412, "medical_codes": 78601 },
  "completed": true
}
```

Три свойства формата держат обещание «скачалось всё»:

- **канонический EJSON** — типы BSON сохраняются точно. Обычный `JSON.stringify`
  превращает `ObjectId` и `Date` в строки, и прежний импорт восстанавливал
  `ObjectId` только у `_id`. Значит все ссылки между документами (`authorId`,
  `patientRef`, `clinicId`…) после круга экспорт → импорт оставались строками, и
  связи молча рвались: дамп выглядел полным, а базой не был;
- **`completed: true` последней строкой** — оборванная закачка даёт файл, который
  не только лишён этой отметки, но и вообще не разбирается как JSON;
- **`stats`** — при загрузке число документов сверяется с заявленным. Если в файле
  1000 документов вместо 1200, коллекция не пишется, а помечается `mismatch`.

Файл одной коллекции имеет тот же формат, поэтому загружается тем же путём и с
теми же проверками.

## Что защищено

| | |
| --- | --- |
| Пароль на каждое действие | `requireAdmin` отвечает «это админ?», проверка пароля — «это он сам, прямо сейчас?». Украденная сессия проходит первое и не проходит второе |
| Аудит | Каждая выгрузка, загрузка и **неудачная попытка** пишутся в `hipaa_audit_logs`. Серия `denied` на выгрузке базы — это и есть след подбора пароля |
| `sessions` не выгружаются | Это живые ключи доступа, им не место в файле на диске |
| `hipaa_audit_logs` и `users` не загружаются | Журнал должен оставаться доказательством, а пользователь с ролью `admin`, заведённый файлом, — скрытый вход, переживающий смену пароля настоящего администратора |
| Поток вместо памяти | Документы уходят в ответ курсором, по одному |

Асимметрия намеренная: журнал аудита и пользователей **скачать можно**
(это нужно для резервной копии), **залить обратно — нет**.

## Про память

Прежний контроллер собирал дамп в один объект и превращал в одну строку через
`JSON.stringify(result, null, 2)`. На боевой базе это 85 МБ данных → ~170 МБ
строки в куче процесса, который обслуживает врачей: на время сборки event loop
стоял, а запас до предела кучи таял по мере роста справочника кодов. Теперь
расход памяти не зависит от размера базы.

Загрузка по-прежнему читает файл целиком — иначе его не разобрать. Предел
размера 512 МБ (`multer`), чтобы случайно выбранный чужой файл не съел память.

## Что в дампе открыто, а что нет

PHI шифруется at-rest (AES-256-CBC, ключ в `.env`, не в базе), а оба
контроллера читают документы **сырыми** — геттеры расшифровки не срабатывают.
Жалобы, анамнез, текст диагноза, имена и телефоны лежат в файле как
`iv:ciphertext`.

Открытым текстом уезжают: **коды МКБ** (`mainDiagnosis.code`), все связи
(какой пациент, у какого врача, в какой клинике, когда), blind-index хэши
(`phoneHash`, `emailHash`) и структура. Пара «пациент + код + дата» — это
диагноз конкретного человека даже без имени. Файл дампа следует считать
псевдонимизированным, а не обезличенным, и обращаться с ним как с медицинской
картой.

## Тесты

`__tests__/admin/dataTransfer.test.js` — 20 проверок, из них ключевые:
типы BSON переживают круг экспорт → импорт, обрезанный файл отбивается **до**
записи в базу, журнал аудита и пользователей загрузкой не пишутся, каждое
действие попадает в `hipaa_audit_logs`.
